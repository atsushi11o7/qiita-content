## RESTful APIとは？

RESTful APIは、Webサービスを設計するためのアーキテクチャスタイルです。

### 基本原則

**REST（Representational State Transfer）** に基づいたAPIで、以下の特徴があります。

| 原則 | 説明 |
|-----|------|
| **リソース指向** | データを「リソース」として扱い、URLで識別する |
| **HTTPメソッドの活用** | GET / POST / PUT / DELETE で操作を表現 |
| **統一インターフェース** | 一貫したURLとメソッドの設計 |

※ RESTful APIには「ステートレス」という原則もあり、サーバーがクライアントの状態を保持しない設計が推奨されますが、今回の記事では認証機能は扱いません（私が未勉強、未実装のため）。

### 具体例

「銘柄（stocks）」というリソースを操作する場合：

| 操作 | HTTPメソッド | URL | 説明 |
|-----|------------|-----|------|
| 一覧取得 | GET | `/api/stocks` | 全銘柄を取得 |
| 個別取得 | GET | `/api/stocks/1` | ID:1の銘柄を取得 |
| 新規作成 | POST | `/api/stocks` | 銘柄を作成 |
| 更新 | PUT / PATCH | `/api/stocks/1` | ID:1の銘柄を更新 |
| 削除 | DELETE | `/api/stocks/1` | ID:1の銘柄を削除 |

### RESTfulのメリット

- **直感的**: URLを見れば何のデータかわかる
- **予測可能**: ルールが統一されているので学習コストが低い
- **疎結合**: フロントエンドとバックエンドを独立して開発できる

Railsの`resources :stocks`は、このRESTfulなルーティングを自動生成してくれる機能です。

## Rails API-only モードのプロジェクト作成

RailsではAPIサーバー専用の軽量な構成として`--api`オプションが提供されています。

```bash
rails new backend --api --database=postgresql
```

### API-onlyモードの特徴

| 機能 | 通常のRails | API-only |
|-----|-----------|----------|
| **ビューレイヤー** | ERB/Haml/Slim | なし（JSON のみ） |
| **ミドルウェア** | セッション、Cookie、CSRF保護 | 最小限 |
| **アセットパイプライン** | あり | なし |
| **ファイルサイズ** | 大きい | 小さい |

### メリット

- **軽量**: 不要なミドルウェアが削除され、レスポンスが高速
- **明確な責務分離**: フロントエンドとバックエンドを完全に分離
- **モバイル対応**: iOS/Androidアプリからも同じAPIを利用可能
- **マイクロサービス化**: 将来的にサービスを分割しやすい

## 今回作るAPIの概要

PostgreSQLに格納されたデータを、APIリクエストに応じて取得・操作して返すAPIを作成します。

```
[クライアント] → HTTPリクエスト → [Rails API] → SQL操作 → [PostgreSQL]
                                                              ↓
[クライアント] ← JSONレスポンス ← [Rails API] ← データ取得 ←───┘
```

## 必要なコンポーネント

この流れを実現するために、3つの主要コンポーネントを実装します。

| コンポーネント | 役割 |
|--------------|------|
| **ルーティング** | どのURLにアクセスしたら、どの処理を実行するかを定義 |
| **コントローラー** | リクエストを受け取り、DB操作を行い、レスポンスを返す |
| **シリアライザー** | DBから取得したデータをJSON形式に整形 |

### ルーティング（routes.rb）

リクエストを適切なコントローラーに振り分けます。

```
GET /api/stocks   → StocksController#index を実行
GET /api/stocks/1 → StocksController#show を実行
```

### コントローラー（Controller）

モデルを通じてDBを操作し、結果を返します。

```ruby
def index
  stocks = Stock.all          # PostgreSQLからデータ取得
  render json: stocks         # JSON形式で返す
end
```

### シリアライザー（Serializer）

クライアントに返すデータの形を決めます。

```ruby
# DBのデータ
Stock(id: 1, code: "7203", name: "トヨタ自動車", internal_note: "メモ")

# シリアライザーで整形後（必要なフィールドだけ）
{ "id": 1, "code": "7203", "name": "トヨタ自動車" }
```

## データベース設計

データベースのテーブル構造を定義します。Railsでは「マイグレーション」と「モデル」という仕組みでデータベースを管理します。

### ER図

今回の例では、3つのテーブルを使用します。

```
┌─────────────┐       ┌─────────────────┐       ┌─────────────────┐
│   stocks    │       │  stock_prices   │       │  predictions    │
├─────────────┤       ├─────────────────┤       ├─────────────────┤
│ id          │───┐   │ id              │   ┌───│ id              │
│ code        │   │   │ stock_id (FK)   │←──┤   │ stock_id (FK)   │←──┐
│ name        │   └──→│ date            │   │   │ target_date     │   │
│ market      │       │ open_price      │   │   │ predicted_price │   │
│ sector      │       │ high_price      │   │   │ actual_price    │   │
│ created_at  │       │ low_price       │   │   │ created_at      │   │
│ updated_at  │       │ close_price     │   │   │ updated_at      │   │
└─────────────┘       │ volume          │   │   └─────────────────┘   │
                      │ created_at      │   │                         │
                      │ updated_at      │   │                         │
                      └─────────────────┘   │                         │
                                            └─────────────────────────┘
```

### マイグレーションファイル

マイグレーションファイルとは、**データベースのテーブル構造を定義するファイル**です。「どんなカラムを持つテーブルを作るか」をRubyのコードで記述します。

#### マイグレーションファイルの作成方法

以下のコマンドでファイルを生成します（私は最初これを知らず手動で作成していました）：

```bash
rails generate migration CreateStocks
```

すると、タイムスタンプ付きのファイルが生成されます：

```
db/migrate/20260110xxxxxx_create_stocks.rb
```

生成されたファイルの中身は空なので、テーブル定義を記述します：

```ruby
class CreateStocks < ActiveRecord::Migration[7.2]
  def change
    create_table :stocks do |t|
      # ここにカラム定義を書く
    end
  end
end
```

定義を書いたら、以下のコマンドでテーブルを作成します：

```bash
rails db:migrate
```

#### 1. 銘柄テーブル（stocks）

```ruby
class CreateStocks < ActiveRecord::Migration[7.2]
  def change
    create_table :stocks do |t|
      t.string :code, null: false, limit: 10      # 銘柄コード（例: "7203"）
      t.string :name, null: false                  # 銘柄名（例: "トヨタ自動車"）
      t.string :market                             # 市場（例: "プライム"）
      t.string :sector                             # 業種（例: "輸送用機器"）

      t.timestamps
    end

    add_index :stocks, :code, unique: true
    add_index :stocks, :market
    add_index :stocks, :sector
  end
end
```

#### 2. 株価テーブル（stock_prices）

```ruby
class CreateStockPrices < ActiveRecord::Migration[7.2]
  def change
    create_table :stock_prices do |t|
      t.references :stock, null: false, foreign_key: true
      t.date :date, null: false                    # 取引日
      t.decimal :open_price, precision: 10, scale: 2   # 始値
      t.decimal :high_price, precision: 10, scale: 2   # 高値
      t.decimal :low_price, precision: 10, scale: 2    # 安値
      t.decimal :close_price, precision: 10, scale: 2  # 終値
      t.bigint :volume                             # 出来高

      t.timestamps
    end

    add_index :stock_prices, [:stock_id, :date], unique: true
    add_index :stock_prices, :date
  end
end
```

#### 3. 予測テーブル（predictions）

```ruby
class CreatePredictions < ActiveRecord::Migration[7.2]
  def change
    create_table :predictions do |t|
      t.references :stock, null: false, foreign_key: true
      t.date :target_date, null: false             # 予測対象日
      t.decimal :predicted_price, precision: 10, scale: 2  # 予測価格
      t.decimal :actual_price, precision: 10, scale: 2     # 実際の価格（後から更新）
      t.decimal :confidence, precision: 5, scale: 4        # 信頼度（0.0〜1.0）

      t.timestamps
    end

    add_index :predictions, [:stock_id, :target_date], unique: true
    add_index :predictions, :target_date
  end
end
```

### モデル定義

モデルとは、**データベースのテーブルをRubyのクラスとして扱うための仕組み**です。テーブル間の関連（1対多など）やバリデーション（入力チェック）を定義します。

#### Stock モデル

`app/models/stock.rb`:

```ruby
class Stock < ApplicationRecord
  has_many :stock_prices, dependent: :destroy
  has_many :predictions, dependent: :destroy

  validates :code, presence: true, uniqueness: true
  validates :name, presence: true

  # スコープ
  scope :by_market, ->(market) { where(market: market) }
  scope :by_sector, ->(sector) { where(sector: sector) }
end
```

#### StockPrice モデル

`app/models/stock_price.rb`:

```ruby
class StockPrice < ApplicationRecord
  belongs_to :stock

  validates :date, presence: true, uniqueness: { scope: :stock_id }
  validates :close_price, presence: true

  # スコープ
  scope :recent, -> { order(date: :desc) }
  scope :in_range, ->(start_date, end_date) { where(date: start_date..end_date) }
end
```

#### Prediction モデル

`app/models/prediction.rb`:

```ruby
class Prediction < ApplicationRecord
  belongs_to :stock

  validates :target_date, presence: true, uniqueness: { scope: :stock_id }
  validates :predicted_price, presence: true

  # スコープ
  scope :recent, -> { order(target_date: :desc) }
  scope :upcoming, -> { where('target_date >= ?', Date.current) }
end
```

## ルーティング設計

ルーティングとは、**「どのURLにアクセスしたら、どのコントローラーのどのアクションを実行するか」を定義する設定**です。`config/routes.rb`に記述します。

```ruby
Rails.application.routes.draw do
  # ヘルスチェック
  get "up" => "rails/health#show", as: :rails_health_check

  # API
  namespace :api do
    # 銘柄
    resources :stocks, only: [:index, :show] do
      # 銘柄に紐づく株価
      resources :stock_prices, only: [:index, :show]
      # 銘柄に紐づく予測
      resources :predictions, only: [:index, :show]

      # カスタムアクション
      member do
        get :latest_price    # /api/stocks/:id/latest_price
      end
    end

    # 株価（全銘柄横断）
    resources :stock_prices, only: [:index]

    # 予測（全銘柄横断）
    resources :predictions, only: [:index] do
      collection do
        get :upcoming        # /api/predictions/upcoming
      end
    end
  end
end
```

### 生成されるエンドポイント一覧

上記のルーティングにより、以下のAPIエンドポイントが自動生成されます。

| HTTPメソッド | パス | 用途 |
|------------|------|------|
| GET | `/api/stocks` | 銘柄一覧 |
| GET | `/api/stocks/:id` | 銘柄詳細 |
| GET | `/api/stocks/:id/latest_price` | 最新株価 |
| GET | `/api/stocks/:stock_id/stock_prices` | 特定銘柄の株価一覧 |
| GET | `/api/stocks/:stock_id/predictions` | 特定銘柄の予測一覧 |
| GET | `/api/stock_prices` | 全株価一覧 |
| GET | `/api/predictions` | 全予測一覧 |
| GET | `/api/predictions/upcoming` | 今後の予測一覧 |

### ルーティングのポイント

#### 1. 名前空間でAPIをグループ化

```ruby
namespace :api do
  # URLに /api/ プレフィックスが付く
end
```

#### 2. ネストしたリソース

```ruby
resources :stocks do
  resources :stock_prices, only: [:index, :show]
end
```

- `/api/stocks/:stock_id/stock_prices` のようなURLが生成される
- 親子関係が明確になる

#### 3. 読み取り専用API

```ruby
resources :stocks, only: [:index, :show]
```

- `only`で必要なアクションのみ生成
- 今回はデータ参照がメインなので、create/update/destroyは除外

## コントローラー実装

コントローラーとは、**リクエストを受け取り、モデルを通じてデータベースを操作し、レスポンスを返す役割**を持つクラスです。APIの場合、JSON形式でレスポンスを返します。

### ApplicationController（共通設定）

すべてのコントローラーの親クラスです。共通のエラーハンドリングなどを定義します。

`app/controllers/application_controller.rb`:

```ruby
class ApplicationController < ActionController::API
  # 共通のエラーハンドリング
  rescue_from ActiveRecord::RecordNotFound, with: :record_not_found

  private

  def record_not_found(exception)
    render json: {
      error: 'Record not found',
      message: exception.message
    }, status: :not_found
  end
end
```

### StocksController

`app/controllers/api/stocks_controller.rb`:

```ruby
module Api
  class StocksController < ApplicationController
    before_action :set_stock, only: [:show, :latest_price]

    # GET /api/stocks
    def index
      stocks = Stock.all

      # フィルタリング
      stocks = stocks.by_market(params[:market]) if params[:market].present?
      stocks = stocks.by_sector(params[:sector]) if params[:sector].present?

      # キーワード検索
      if params[:keyword].present?
        stocks = stocks.where('name LIKE ? OR code LIKE ?',
                              "%#{params[:keyword]}%",
                              "%#{params[:keyword]}%")
      end

      # ソート
      stocks = stocks.order(code: :asc)

      render json: stocks, each_serializer: StockSerializer
    end

    # GET /api/stocks/:id
    def show
      render json: @stock, serializer: StockDetailSerializer
    end

    # GET /api/stocks/:id/latest_price
    def latest_price
      price = @stock.stock_prices.recent.first

      if price
        render json: price, serializer: StockPriceSerializer
      else
        render json: { error: 'No price data available' }, status: :not_found
      end
    end

    private

    def set_stock
      @stock = Stock.find(params[:id])
    end
  end
end
```

### StockPricesController

`app/controllers/api/stock_prices_controller.rb`:

```ruby
module Api
  class StockPricesController < ApplicationController
    before_action :set_stock, only: [:index, :show], if: -> { params[:stock_id].present? }

    # GET /api/stocks/:stock_id/stock_prices
    # GET /api/stock_prices
    def index
      prices = if @stock
                 @stock.stock_prices
               else
                 StockPrice.includes(:stock)
               end

      # 日付範囲でフィルタ
      if params[:start_date].present? && params[:end_date].present?
        prices = prices.in_range(params[:start_date], params[:end_date])
      end

      # 直近N件
      prices = prices.recent.limit(params[:limit] || 100)

      render json: prices, each_serializer: StockPriceSerializer
    end

    # GET /api/stocks/:stock_id/stock_prices/:id
    def show
      price = @stock.stock_prices.find(params[:id])
      render json: price, serializer: StockPriceSerializer
    end

    private

    def set_stock
      @stock = Stock.find(params[:stock_id])
    end
  end
end
```

### PredictionsController

`app/controllers/api/predictions_controller.rb`:

```ruby
module Api
  class PredictionsController < ApplicationController
    before_action :set_stock, only: [:index, :show], if: -> { params[:stock_id].present? }

    # GET /api/stocks/:stock_id/predictions
    # GET /api/predictions
    def index
      predictions = if @stock
                      @stock.predictions
                    else
                      Prediction.includes(:stock)
                    end

      predictions = predictions.recent.limit(params[:limit] || 50)

      render json: predictions, each_serializer: PredictionSerializer
    end

    # GET /api/predictions/upcoming
    def upcoming
      predictions = Prediction.includes(:stock)
                              .upcoming
                              .order(target_date: :asc)
                              .limit(params[:limit] || 20)

      render json: predictions, each_serializer: PredictionSerializer
    end

    # GET /api/stocks/:stock_id/predictions/:id
    def show
      prediction = @stock.predictions.find(params[:id])
      render json: prediction, serializer: PredictionSerializer
    end

    private

    def set_stock
      @stock = Stock.find(params[:stock_id])
    end
  end
end
```

### コントローラー実装のポイント

#### 1. 名前空間の明示

```ruby
module Api
  class StocksController < ApplicationController
    # ...
  end
end
```

`api/`ディレクトリに配置されたコントローラーは、`Api`モジュールで囲む必要があります。

#### 2. before_actionで共通処理

```ruby
before_action :set_stock, only: [:show, :latest_price]
```

複数のアクションで使う処理を共通化できます。

#### 3. 条件付きbefore_action

```ruby
before_action :set_stock, only: [:index], if: -> { params[:stock_id].present? }
```

ネストしたルート（`/api/stocks/:stock_id/stock_prices`）とそうでないルート（`/api/stock_prices`）で処理を分岐できます。

#### 4. スコープの活用

```ruby
prices = prices.recent.limit(params[:limit] || 100)
```

モデルで定義したスコープを使うことで、コードの可読性が向上します。

## シリアライザー実装

シリアライザーとは、**モデルのデータをJSON形式に変換する際のフォーマットを定義するクラス**です。どのフィールドを出力するか、どのように加工するかを指定できます。

### インストール

`Gemfile`に追加してインストールします：

```ruby
gem 'active_model_serializers', '~> 0.10.0'
```

```bash
bundle install
```

### StockSerializer（一覧用）

シンプルに必要なフィールドだけを出力するシリアライザーです。

`app/serializers/stock_serializer.rb`:

```ruby
class StockSerializer < ActiveModel::Serializer

end
```

```json
{
  "id": 1,
  "code": "7203",

```

### StockDetailSerializer（詳細用）

関連データも含めた詳細なシリアライザーです。

`app/serializers/stock_detail_serializer.rb`:

```ruby
class StockDetailSerializer < ActiveModel::Serializer
  attributes :id, :code, :name, :market, :sector, :created_at, :updated_at

  # 最新の株価を含める
  attribute :latest_price

  # 直近の予測を含める
  attribute :latest_prediction

  def latest_price
    price = object.stock_prices.recent.first
    return nil unless price

    {
      date: price.date,
      close_price: price.close_price,
      volume: price.volume
    }
  end
```

### PredictionSerializer

`app/serializers/prediction_serializer.rb`:

```ruby
class PredictionSerializer < ActiveModel::Serializer
  attributes :id, :target_date, :predicted_price, :actual_price, :confidence

  # 銘柄情報
  attribute :stock, if: :include_stock?

  # 予測精度（実績がある場合）
  attribute :accuracy, if: :has_actual_price?

  def stock
    {
      id: object.stock.id,
      code: object.stock.code,
      name: object.stock.name
    }
  end

  def accuracy
    return nil unless object.actual_price.present?

    diff = (object.predicted_price - object.actual_price).abs
    error_rate = (diff / object.actual_price * 100).round(2)
    {
      error_rate: error_rate,
      difference: diff.round(2)
    }
  end

  def include_stock?
    !instance_options[:scope]&.dig(:nested)
  end

  def has_actual_price?
    object.actual_price.present?
  end
end
```

```json
  "stock": {
    "id": 1,
    "code": "7203",
    "name": "トヨタ自動車"
  },
```

## CORS設定

CORSとは、**異なるオリジン（ドメイン）間でのリクエストを許可するための仕組み**です。フロントエンド（Next.js）とバックエンド（Rails API）が異なるポートで動作する場合、CORS設定が必要です。

### インストール

`Gemfile`:

```ruby
gem 'rack-cors'
```

```bash
bundle install
```

### 設定

`config/initializers/cors.rb`:

```ruby
Rails.application.config.middleware.insert_before 0, Rack::Cors do
  allow do
    origins 'localhost:3000', '127.0.0.1:3000'  # Next.jsの開発サーバー

    resource '*',
      headers: :any,
      methods: [:get, :post, :put, :patch, :delete, :options, :head]
  end
end
```

この設定により、`localhost:3000`で動作するNext.jsからAPIにアクセスできるようになります。
