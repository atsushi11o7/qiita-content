# Qiita 公開・更新前チェック

CLAUDE.md の「記事執筆のルール」への **適合** を機械的に判定する。判断ベースの編集レビュー（流れ、論旨、文体の読みやすさなど）は `content-reviewer` エージェントの責務。

## 対象ファイルの特定

ユーザーが対象記事を明示していなければ、`public/` 内のファイル一覧を提示して選んでもらう。

## チェック項目

### 1. frontmatter

CLAUDE.md の frontmatter 表の制約を満たしているか確認する。

- `title` が存在し、極端に長くないか
- **`tags` が 1〜5 個あり、各タグが空文字でないか（0 個や空タグ `- ''` だと publish できない。生成直後は空タグが入っているので最優先で確認）**
- `private` がブール値（`true` / `false`）か
- `id` / `updated_at` を手で壊していないか（`id` は空または採番済みの値。勝手に書き換え・削除していないか）

`private` の値が `false` / `true` のどちらであるべきかは呼び出し側 Skill の責務で、本スキルでは判定しない。

### 2. 本文構造

- 本文の先頭が `##` から始まる（`#` を使っていない）
- 見出しレベルが飛んでいない（`##` の次に `####` など）
- HTML コメント（`<!-- ... -->`）が残っていない（骨組みのメモは公開前に削除）

### 3. コードブロック

- すべての ` ``` ` ブロックに言語指定がある
  - 言語指定なしを見つけたら、内容から推測して提案する

### 4. 画像

- すべての画像参照（`![...](...)`）について：
  - **Qiita にアップロードされたホスト URL（`https://...`）になっている**
  - **ローカルの相対パス・絶対パス（`./images/...`、`/images/...`、`images/...`）になっていないか**（Qiita では表示されないため検出したら指摘し、Qiita の画像アップロードページでアップロードして URL を貼るよう案内する）
  - alt テキストが空でない

### 5. リンク

- Markdown リンク（`[text](url)`）の text が空でない
- 明らかに壊れた URL（`http` / `https` で始まらない外部リンク）がない

### 6. 表記ルール

- 文体が「です・ます調」で統一されている
- 半角英数字の前後に半角スペースがある
- 用語の表記揺れがない（CLAUDE.md の「カタカナ語・固有名詞」セクション参照：Qiita / GitHub / Dev Container / VS Code など）

## アウトプット形式

```
## 公開前チェック結果

### ❌ 修正が必要
- [箇所] [問題] → [修正案]

### ✅ 問題なし
- frontmatter / tags / 構造 / コードブロック / 画像 / リンク / 表記
```

問題があれば箇所と修正案を、無ければ ✅ のみ報告する。

## 修正の進め方

- 機械的に修正できるもの（表記揺れ、半角スペース、コードブロックの言語指定など）は、ユーザー承認後に一括修正する
- 修正後は再度このスキルを実行することを推奨する
- 公開前は機械チェック後に **`content-reviewer` の編集レビューも併用** することを案内する

## 重要な制約

- このスキル単体では `private` の値を変更しない（`private` の確定は `/publish-article` で扱う）
- `id` / `updated_at` を書き換えない（Qiita CLI の管理対象）
- ユーザー承認なしに本文の構造を大きく変えない
- 文章の質や流れに関する判断はこのスキルの責務外（`content-reviewer` に委ねる）
