# はじめに

この記事では、サーバ上にデプロイしたRails APIを**Nginxをリバースプロキシ**として設定し、**Let's Encryptで無料SSL証明書**を取得してHTTPS化する方法を解説します。

[こちらのサイト](https://www.fumikabu.com/)をデプロイする際に学習した内容のおぼえがきです。

https://www.fumikabu.com/

### なぜHTTPS化が必要？

本番環境でHTTPSが必須な理由は以下の通りです。

| 理由 | 説明 |
|-----|-----|
| セキュリティ | 通信が暗号化され、盗聴・改ざんを防止 |
| 信頼性 | ブラウザが「安全な接続」と表示 |
| SEO | GoogleはHTTPSサイトを優遇 |
| API連携 | 多くの外部サービスがHTTPS必須 |
| Cookie | Secure属性のCookieはHTTPSでのみ送信可能 |

### 最終的な構成

```
インターネット
    ↓ HTTPS (443)
Nginx (SSL終端 + リバースプロキシ)
    ↓ HTTP (localhost:3000)
Rails API (Docker)
```

# Nginxとは？

**Nginx**は、高性能なWebサーバー/リバースプロキシサーバーです。

### Nginxの主な用途

| 用途 | 説明 |
|-----|------|
| **Webサーバー** | 静的ファイル（HTML, CSS, 画像）を高速に配信 |
| **リバースプロキシ** | クライアントとアプリケーションサーバーの間に立ち、リクエストを中継 |
| **ロードバランサー** | 複数のサーバーにリクエストを分散 |
| **SSL終端** | HTTPS通信の暗号化/復号化を担当 |

### なぜNginxを使うのか？

Railsアプリ（Puma）だけでも動作しますが、Nginxを前段に置くことで以下のメリットがあります。

```
【Nginxなし】
インターネット → Rails (Puma) :3000

【Nginxあり】
インターネット → Nginx :80/443 → Rails (Puma) :3000
```

| メリット | 説明 |
|---------|------|
| **SSL/TLS処理** | 暗号化処理をNginxが担当し、Railsの負荷を軽減 |
| **静的ファイル配信** | 画像やCSSをNginxが直接配信（高速） |
| **セキュリティ** | 不正なリクエストをNginxでブロック |
| **ポート変換** | 80/443番ポートで受けて、内部の3000番に転送 |
| **バッファリング** | 遅いクライアントからの接続をNginxが吸収 |

# Let's Encryptとは？

**Let's Encrypt**は、無料でSSL/TLS証明書を発行してくれる認証局（CA: Certificate Authority）です。

### 基本情報

| 項目 | 内容 |
|-----|------|
| 運営 | Internet Security Research Group（ISRG）という非営利団体 |
| 料金 | **完全無料** |
| 有効期限 | 90日間（自動更新で運用） |
| 発行数 | 全世界で数億以上のサイトが利用 |

### certbotについて

**certbot**は、Let's Encryptの証明書を取得・更新するための公式クライアントツールです。

```bash
# certbotでできること
certbot --nginx -d example.com  # 証明書の取得 & Nginx自動設定
certbot renew                    # 証明書の更新
certbot certificates             # 証明書の一覧表示
```

:::note info
certbotを使えば、コマンド1つでSSL証明書の取得からNginxの設定まで自動で行ってくれます。
:::

# 1. DNS設定（サブドメインの追加）

## サブドメインとは？

APIサーバーには、サブドメインを使うのが一般的です。

```
メインドメイン: example.com（フロントエンド用）
サブドメイン:  api.example.com（バックエンドAPI用）
```

## ドメイン管理画面でDNSレコードを追加

お使いのドメインレジストラ（Xserverドメイン、お名前.comなど）の管理画面で、以下のAレコードを追加します。

| 項目 | 入力値 | 説明 |
|-----|-------|------|
| ホスト名 | `api` | `api.example.com`になる |
| 種別 | `A` | IPv4アドレスを指定 |
| 内容 | VPSのIPアドレス | 例: `xxx.xx.xx.xxx` |
| TTL | `3600` | 1時間（デフォルトでOK） |

# 3. Nginx設定ファイルの作成

## 3-1. 設定ファイルのディレクトリ構造

```
/etc/nginx/
├── nginx.conf              # メイン設定ファイル
├── sites-available/        # 利用可能なサイト設定
│   └── api.example.com     # ← ここに作成
└── sites-enabled/          # 有効なサイト設定（シンボリックリンク）
```

## 3-2. 設定ファイルの作成

```bash
vi /etc/nginx/sites-available/api.example.com
```

以下の内容を記述します（初期設定・HTTPのみ）:

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 3-3. 設定の解説

| ディレクティブ | 説明 |
|--------------|------|
| `listen 80` | ポート80（HTTP）でリクエストを受け付ける |
| `server_name` | このドメインへのリクエストを処理 |
| `proxy_pass` | Railsアプリ（ポート3000）にリクエストを転送 |
| `proxy_set_header` | 元のリクエスト情報をRailsに渡す |

## 3-4. 設定ファイルの有効化

```bash
# シンボリックリンクを作成
ln -s /etc/nginx/sites-available/api.example.com /etc/nginx/sites-enabled/

# デフォルト設定を無効化（オプション）
rm /etc/nginx/sites-enabled/default

# 設定ファイルの文法チェック
nginx -t

# Nginxを再起動
systemctl restart nginx
```

**文法チェック成功時の出力**:

```
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

# 5. Let's EncryptでSSL証明書を取得

## 5-1. certbotの実行

```bash
certbot --nginx -d api.example.com
```

## 5-2. 対話形式の質問に回答

### 質問1: メールアドレス

```
Enter email address (used for urgent renewal and security notices):
```

証明書の有効期限が近づくと通知が届きます。有効なメールアドレスを入力してください。

### 質問2: 利用規約への同意

```
Please read the Terms of Service at https://letsencrypt.org/documents/LE-SA-v1.3-September-21-2022.pdf.
You must agree in order to register with the ACME server. Do you agree?
```

→ `Y`を入力してEnter

### 質問3: EFFからのメール受信（オプション）

```
Would you be willing to share your email address with the Electronic Frontier Foundation?
```

→ 私は`N`を入力しました（任意）

### 質問4: HTTPSリダイレクト

```
Please choose whether or not to redirect HTTP traffic to HTTPS, removing HTTP access.
1: No redirect - Make no further changes to the webserver configuration.
2: Redirect - Make all requests redirect to secure HTTPS access.
```

→ `2`を入力してEnter（**推奨**: HTTPを自動的にHTTPSにリダイレクト）

## 5-3. 証明書取得の完了

**成功時の出力**:

```
Successfully received certificate.
Certificate is saved at: /etc/letsencrypt/live/api.example.com/fullchain.pem
Key is saved at:         /etc/letsencrypt/live/api.example.com/privkey.pem
This certificate expires on 2026-04-03.

Congratulations! You have successfully enabled HTTPS on https://api.example.com
```

:::note info
certbotが自動的にNginx設定を更新し、SSL証明書のパスやHTTPSリダイレクトの設定を追加してくれます。
:::

## 5-4. 自動更新後のNginx設定

certbotによって設定ファイルは以下のように更新されます:

```nginx
server {
    server_name api.example.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    listen 443 ssl; # managed by Certbot
    ssl_certificate /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}

server {
    if ($host = api.example.com) {
        return 301 https://$host$request_uri;
    }

    listen 80;
    server_name api.example.com;
    return 404;
}
```

# 7. Rails側の設定（force_ssl）

## 7-1. force_sslの有効化

Rails本番環境では、すべての通信をHTTPSに強制します。

```bash
vi /path/to/your/app/config/environments/production.rb
```

以下の行を`true`に変更:

```ruby
# 変更前
config.force_ssl = false

# 変更後
config.force_ssl = true
```

## 7-2. アプリケーションの再起動

設定変更を反映するため、Railsアプリを再起動します。

```bash
# Docker使用の場合
cd /opt/your-app/docker
docker-compose down
docker-compose up -d --build
```

# 8. ポート3000を閉じる（セキュリティ強化）

Nginxを経由してアクセスできるようになったので、直接ポート3000にアクセスする必要はありません。

## 8-1. ファイアウォール設定

ポート3000の許可ルールを**削除**します。

**最終的な設定**:

| プロトコル | ポート | 説明 |
|----------|--------|------|
| TCP | 22 | SSH |
| TCP | 80 | HTTP（HTTPSへリダイレクト） |
| TCP | 443 | HTTPS |

このようになると思います。（再掲）
![スクリーンショット 2026-01-17 173027.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/3121510/8700887d-efcd-4d5a-bdc4-a3a093a0333d.png)


## 8-2. 確認

```bash
# ポート3000への直接アクセス → 失敗するはず
curl http://your-server-ip:3000/up
# → タイムアウトまたは接続拒否

# Nginx経由のアクセス → 成功するはず
curl https://api.example.com/up
# → 正常なレスポンス
```

:::note
**重要**: ポート3000を閉じることで、外部からの直接アクセスをブロックし、すべてのトラフィックがNginx（HTTPS）を経由するようになります。
:::

# 9. SSL証明書の自動更新

Let's Encryptの証明書は**90日間有効**です。certbotが自動的に更新してくれます。

## 9-1. 自動更新の確認

```bash
systemctl list-timers | grep certbot
```

**出力例**:

```
Sun 2025-02-02 00:00:00 JST  certbot.timer  certbot.service
```

## 9-2. 手動更新のテスト

```bash
certbot renew --dry-run
```

**成功時の出力**:

```
Congratulations, all simulated renewals succeeded:
  /etc/letsencrypt/live/api.example.com/fullchain.pem (success)
```

:::note info
`--dry-run`オプションは実際には更新せず、更新が正常に動作するかテストするだけです。
:::
