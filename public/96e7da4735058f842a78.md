# はじめに

個人ブログを Next.js App Router + microCMS で構築しています。

microCMS は日本製のヘッドレス CMS で、API 経由でコンテンツを取得できるため、Next.js との相性が非常に良いです。公式 SDK（`microcms-js-sdk`）を使えば型安全にデータを扱うことができます。

この記事では、実際にブログサイトを構築した経験をもとに、私の microCMS 活用例を紹介します。
主に以下の内容を説明します。

- microCMS のセットアップと API スキーマ設計
- TypeScript での型定義
- データ取得関数の実装（一覧・詳細・カテゴリ・タグ）
- フィールド選択によるレスポンス軽量化
- Qiita や Zenn の記事と統一的に扱う変換パターン

# 1. microCMS のスキーマ設計

microCMS の管理画面で、以下の API を作成しました。

### ブログ記事（`blogs`）- リスト形式

| フィールド ID | 表示名 | 種類 |
|---|---|---|
| `title` | タイトル | テキストフィールド |
| `slug` | スラッグ | テキストフィールド |
| `publishDate` | 公開日 | 日時 |
| `updateDate` | 更新日 | 日時 |
| `content` | 本文 | リッチエディタ |
| `eyecatch` | アイキャッチ | 画像 |
| `category` | カテゴリ | コンテンツ参照（カテゴリ） |
| `tags` | タグ | 複数コンテンツ参照（タグ） |

### カテゴリ（`categories`）- リスト形式

| フィールド ID | 表示名 | 種類 |
|---|---|---|
| `name` | カテゴリ名 | テキストフィールド |
| `slug` | スラッグ | テキストフィールド |

### タグ（`tags`）- リスト形式

| フィールド ID | 表示名 | 種類 |
|---|---|---|
| `name` | タグ名 | テキストフィールド |
| `slug` | スラッグ | テキストフィールド |

**ポイント:** `slug` フィールドを自分で定義しています。microCMS が自動付与する `id` は `"xk3f9a..."` のようなランダム文字列になるため、URL に使いたい場合は自分で `slug` を管理したほうが可読性が高くなります。

# 2. SDK のインストールと環境変数

## インストール

```bash
npm install microcms-js-sdk
```

## 環境変数の設定

`.env.local` に microCMS の認証情報を設定します。

```bash
# microCMS設定
MICROCMS_SERVICE_DOMAIN=your-service-domain
MICROCMS_API_KEY=your-api-key
```

`MICROCMS_SERVICE_DOMAIN` は microCMS の管理画面 URL `https://your-service-domain.microcms.io` のサブドメイン部分です。API キーは管理画面の「サービス設定 > API キー」から取得できます。

:::note warn
`.env.local` は `.gitignore` に含めて、API キーをリポジトリにコミットしないように注意してください。Next.js ではデフォルトで `.env.local` が `.gitignore` に追加されています。
:::

# 3. TypeScript で型を定義する

microCMS のスキーマに対応する TypeScript の型を定義します。

```typescript
// src/types/article.ts
import type { MicroCMSImage, MicroCMSListContent } from 'microcms-js-sdk';

export type Tag = {
  name: string;
  slug: string;
};

export type Category = {
  name: string;
  slug: string;
};

/**
 * microCMS記事のAPIスキーマ（自分で定義したフィールド）
 */
export interface MicroCMSArticleSchema {
  title: string;
  slug: string;
  publishDate: string;
  updateDate: string;
  /** リッチエディタ（HTML文字列） */
  content: string;
  eyecatch: MicroCMSImage;
  category: Category;
  tags: Tag[];
}

/**
 * microCMS記事の完全な型（SDKが自動付与するフィールド含む）
 * getList / getListDetail の戻り値はこの型になる
 */
export type MicroCMSArticle = MicroCMSArticleSchema & MicroCMSListContent;
```

**ポイント:**

- `MicroCMSImage` は SDK が提供する型で、`url` や `width`, `height` を含みます
- `MicroCMSListContent` は SDK がリスト取得時に自動付与する `id`, `createdAt`, `updatedAt`, `publishedAt`, `revisedAt` を含みます
- `MicroCMSArticleSchema`（自分で定義したフィールド）と `MicroCMSListContent`（SDK 自動付与）を intersection で合成することで、完全な型を得ています

# 4. microCMS クライアントの作成

```typescript
// src/libs/microcms.ts
import { createClient } from 'microcms-js-sdk';
import type { MicroCMSQueries } from 'microcms-js-sdk';
import type { MicroCMSArticleSchema, Category, Tag } from '@/types/article';

if (!process.env.MICROCMS_SERVICE_DOMAIN) {
  throw new Error('MICROCMS_SERVICE_DOMAIN is required');
}

if (!process.env.MICROCMS_API_KEY) {
  throw new Error('MICROCMS_API_KEY is required');
}

export const client = createClient({
  serviceDomain: process.env.MICROCMS_SERVICE_DOMAIN,
  apiKey: process.env.MICROCMS_API_KEY,
  retry: true,
});
```

`retry: true` を指定すると、一時的なネットワークエラー時に SDK が自動でリトライしてくれます。

# 5. データ取得関数の実装

## 記事一覧の取得（軽量版）

```typescript
/**
 * ブログ記事一覧を取得（カード表示用。contentを除外して軽量化）
 */
export const getBlogs = async (queries?: MicroCMSQueries) => {
  return client.getList<Omit<MicroCMSArticleSchema, 'content' | 'updateDate'>>({
    endpoint: 'blogs',
    queries: {
      fields: ['id', 'title', 'slug', 'publishDate', 'eyecatch', 'category', 'tags'],
      ...queries,
    },
  });
};
```

**ポイント: `fields` で必要なフィールドだけを指定する**

一覧ページではリッチエディタの `content`（HTML 本文）は不要です。`fields` を指定することで、レスポンスサイズを削減できます。

型レベルでも `Omit<MicroCMSArticleSchema, 'content' | 'updateDate'>` として除外したフィールドにアクセスできないようにしています。

## 記事詳細の取得（スラッグ指定）

```typescript
/**
 * ブログ記事の詳細を取得（slug指定）
 */
export const getBlogBySlug = async (slug: string, queries?: MicroCMSQueries) => {
  const response = await client.getList<MicroCMSArticleSchema>({
    endpoint: 'blogs',
    queries: {
      filters: `slug[equals]${slug}`,
      ...queries,
    },
  });

  if (response.contents.length === 0) {
    throw new Error(`Blog with slug "${slug}" not found`);
  }

  return response.contents[0];
};
```

microCMS は `getListDetail` で `id` を指定して取得するのが一般的ですが、URL に使いたいのは `slug` なので、`filters` を使って `slug` で検索しています。

## カテゴリ・タグ一覧の取得

```typescript
/**
 * カテゴリー一覧を取得
 */
export const getCategories = async (queries?: MicroCMSQueries) => {
  return client.getList<Category>({
    endpoint: 'categories',
    queries,
  });
};

/**
 * タグ一覧を取得
 */
export const getTags = async (queries?: MicroCMSQueries) => {
  return client.getList<Tag>({
    endpoint: 'tags',
    queries,
  });
};
```

# 6. Next.js App Router で使う

App Router の Server Component でデータを取得します。

## 記事一覧ページの例

```typescript
// src/app/blog/page.tsx
import { getBlogs, getCategories } from '@/libs/microcms';
import { transformMicroCMSArticle } from '@/libs/transformers';
import { BlogPageClient } from './BlogPageClient';

export default async function BlogPage() {
  const [blogsResponse, categoriesResponse] = await Promise.all([
    getBlogs(),
    getCategories(),
  ]);

  const articles = blogsResponse.contents.map(transformMicroCMSArticle);
  const categories = categoriesResponse.contents;

  return <BlogPageClient articles={articles} categories={categories} />;
}
```

Server Component で `async/await` を直接使えるのが App Router の利点です。`Promise.all` で並行取得することでパフォーマンスも最適化できます。

## 記事詳細ページの例

```typescript
// src/app/blog/[slug]/page.tsx
import { getBlogBySlug } from '@/libs/microcms';
import { notFound } from 'next/navigation';

type Props = {
  params: Promise<{ slug: string }>;
};

export default async function BlogDetailPage({ params }: Props) {
  const { slug } = await params;

  try {
    const article = await getBlogBySlug(slug);

    return (
      <article>
        <h1>{article.title}</h1>
        <div dangerouslySetInnerHTML={{ __html: article.content }} />
      </article>
    );
  } catch {
    notFound();
  }
}
```

# 7. 複数ソースの記事を統一的に扱う

おまけです。microCMS の記事だけでなく、Qiita 等に投稿した記事も一緒に表示したいと思ったため、統一的な `Article` インターフェースを定義し、各ソースのデータを変換する Transformer パターンを作成しました。

## 統一インターフェース

```typescript
export type ArticleSource = 'microcms' | 'qiita' | 'zenn' | 'note';

export interface Article {
  id: string;
  title: string;
  description?: string;
  publishedAt: string;
  category: string[];
  source: ArticleSource;
  tags?: string[];
  /** microCMS: `/blog/[slug]` / Qiita・Zenn: 外部URL */
  href: string;
  thumbnail?: string;
}
```

## Transformer 関数

```typescript
// src/libs/transformers.ts
import type { Article, MicroCMSArticle } from '@/types/article';

/**
 * microCMSの記事データを統一されたArticle型に変換
 */
export function transformMicroCMSArticle(data: MicroCMSArticle): Article {
  return {
    id: data.id,
    title: data.title,
    publishedAt: data.publishDate,
    category: [data.category.name],
    source: 'microcms',
    tags: data.tags?.map((tag) => tag.name) || [],
    href: `/blog/${data.slug}`,
    thumbnail: data.eyecatch?.url,
  };
}
```

**ポイント:**

- microCMS の `category` はコンテンツ参照（オブジェクト）ですが、`Article` では `string[]` に変換しています
- `tags` も同様にオブジェクト配列から名前の文字列配列に変換しています
- `href` は microCMS の場合は内部リンク、外部サービスの場合は外部 URL になります

この Transformer パターンのおかげで、UI コンポーネント（`ArticleCard` など）は `Article` 型だけを知っていれば良く、データソースごとの差異を意識する必要がありません。

```
[microCMS API] → transformMicroCMSArticle() → Article
[Qiita RSS]    → transformQiitaArticle()    → Article    →  ArticleCard
[Zenn RSS]     → transformZennArticle()     → Article
```
