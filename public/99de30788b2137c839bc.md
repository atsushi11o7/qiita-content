# はじめに

Next.jsでブログサイトを作成していたのですが、ブログが表示される前の演出として **ターミナル風のブートスクリーン** にASCIIアートのロゴを表示しようとしていました。ところが、**文字がずれて崩れる**という問題に遭遇しました。

（ページにアクセスするとこのような表示が出た後に、サイト本体へ遷移する演出を作っていました）

![boot-screen](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/3121510/fba0306d-dfb0-4bb9-983b-a85bf410b9c7.jpeg)

一見するとモノスペースフォントを指定しているのに、なぜか文字幅が不揃いになってしまう……。  
調査したところ、原因は主に **「フォントフォールバック」** と **「ホワイトスペース処理」** の2つでした。本記事では、その内容をまとめます。

---

## TL;DR（要約）

- **問題:** モノスペースフォントでもBox Drawing文字（`█`, `╔`, `╗` など）が崩れる
- **原因1:** 使用フォント（例：Geist Mono）の **Box Drawing文字のカバレッジが十分でない** 場合、別フォントへフォールバックして文字幅が不揃いになる
- **原因2:** `white-space` 未指定だとスペースが潰れたり折り返しが発生する
- **解決:** Box Drawing対応フォントを優先する `font-family` を明示 + `white-space: pre` + `pre` タグ推奨（+ 横スクロール/行間調整）

---

# 根本原因：2つの要因

ASCIIアートが崩れる原因は、主に次の2つでした。

---

## 原因1：フォントフォールバック（主要因）

### Box Drawing文字とは

Unicodeには罫線を描くための文字カテゴリがあり、例えば次のようなものが含まれます。

- `█`（U+2588）: Full Block
- `╔╗╚╝║═`（U+2550–U+255D）: Box Drawing

これらは **モノスペースフォントで同じ幅になることが期待される** 文字です。

### 何が起きていたか

私の環境では、Next.js の `next/font` を使って `--font-geist-mono` を当てていたのですが、（少なくとも私の環境では）**Geist Mono が Box Drawing を十分にカバーしておらず**、該当文字が別フォントにフォールバック（その文字のデータが無い場合、代わりに別のフォントを使う仕組み）していました。

:::note
Tailwind のデフォルト `font-mono` はOS依存のフォントスタックです。

```css
ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas,
Liberation Mono, Courier New, monospace
```
Next.js の next/font でカスタムフォントを優先している場合、
特定文字だけがフォールバックしやすくなることがあります。
:::


ブラウザの挙動は次のようなイメージです：

1. まず Geist Mono（など）でASCII文字を描画
2. フォントに該当グリフがない文字（`█`, `╔`, `╗` など）を検知
3. システムのフォールバックフォント（例：Apple Symbols / Segoe UI Symbol / Noto Sans Symbols など）で描画

フォールバック先のフォントは **幅が一致するとは限らない** ため、ASCIIアートの横幅が揃わなくなります。


---

## 原因2：ホワイトスペース処理

ASCIIアートは **スペースの数もレイアウトの一部** です。  
しかし、デフォルトのHTML描画では以下が起きます。

- 連続スペースが1つに圧縮される
- 行末スペースが削除される
- 幅が足りないと折り返しやレイアウト崩れの原因になることがある

ASCIIアート表示では、少なくとも以下を意識すると安定します。

```css
white-space: pre;   /* 連続スペース・改行を保持（自動折り返しは行わず、横にはみ出す） */
overflow-x: auto;   /* 横スクロールを許可 */
line-height: 1;     /* 行間のズレ（上下の見た目）を抑える */
```

Tailwindなら例えば：

```tsx
<pre className="whitespace-pre leading-none overflow-x-auto font-mono">
```

---

# 解決策：Box Drawing対応フォントを明示的に指定する

## ASCII文字だけ使うべき？
Box Drawing文字は本来モノスペース用途のUnicodeで、問題は「文字」ではなく **フォントのUnicodeカバレッジ** にあります。  
Box Drawingに対応したモノスペースフォントを使えば、安定して表示できます。

---

## Box Drawing対応フォント例

（※環境やバージョンにより差はありますが）一般的に次のようなフォントはBox Drawingを含むことが多いです。

- **JetBrains Mono** 
- **Fira Code** 
- **Cascadia Code** 
- **Consolas** 
- **Menlo** 
- **DejaVu Sans Mono** 
- **Courier New** 

---

## 推奨：`<pre>` タグで表示する

`pre` は意味的にも適切で、コピー&ペースト時の保持やブラウザ側の挙動も予測しやすくなります。

```tsx
// ✅ 推奨：preタグ + Tailwind
<pre
  className="whitespace-pre leading-none overflow-x-auto font-mono text-sm p-6"
  style={{
    fontFamily: [
      '"JetBrains Mono"',
      '"Fira Code"',
      '"Cascadia Code"',
      'Consolas',
      'Menlo',
      '"DejaVu Sans Mono"',
      '"Courier New"',
      'var(--font-geist-mono)', // 元のフォントは後方に配置
      'monospace',              // セーフティネット
    ].join(', ')
  }}
>
  {banner.join('\n')}
</pre>
```

---

## ポイント

1. **Box Drawing対応フォントを優先**して並べる  
2. `var(--font-geist-mono)` は後方に配置（ASCII用途のフォールバックとして残す）  
3. 最後に `monospace` を指定してセーフティネットを張る  
4. `white-space: pre`（または `whitespace-pre`）でスペース・改行を保持  
5. `overflow-x: auto` で横スクロールを許可（折り返しより崩れにくい）  
6. `line-height: 1`（または `leading-none`）で行間の見た目ズレを抑える  


これでほとんどの場合は解決できると思います。

---

# 結果

この修正により、すべての文字が同一フォント（JetBrains Mono など）で描画され、文字幅が揃ってASCIIアートが正しく表示されるようになりました。

## Before（崩れている状態）

- カスタムフォント + システムフォールバック
- 文字幅がバラバラで斜めにずれる
- ホワイトスペース処理次第で崩れが増幅する

## After（修正後）

- Box Drawing対応フォントで統一
- すべての文字幅が揃って表示が安定
- スペース保持・横スクロール・行間調整で崩れを抑制

# まとめ

- モノスペースフォントでも、すべてのUnicode文字をカバーしているわけではない
- Box Drawing文字を使う場合は、**フォントのグリフカバレッジ** が重要
- `font-family` を工夫して **意図しないフォント切り替え（フォールバック）** を防ぐ
- `white-space: pre` と `overflow-x: auto` でスペース保持と表示崩れを抑える
- `<pre>` タグを使うと semantic かつ扱いやすい

同じように「ASCIIアートが崩れる…」と悩んでいる方の参考になれば嬉しいです。
