## 概要

Webアプリケーション開発において、チーム間での環境差異やホスト環境の汚染を防ぐため、Devcontainerを使った開発環境を構築します。

今回は、**Next.js + Node.js 24** 構成で、シンプルかつ軽量な開発環境テンプレートを紹介します。

過去に書いた以下の記事の Next.js Ver です。

https://qiita.com/atsushi11o7/items/694e878558c7a63912bf

https://qiita.com/atsushi11o7/items/c572b07869d0d5236d95

## Devcontainer を使う利点

VSCodeのRemote Containers（devcontainer）機能を使えば、以下のようなメリットがあります。

- **開発環境の再現性が高い** - チームメンバー全員が同じ環境で開発できる
- **ホスト環境を汚さない** - Node.jsやnpmパッケージをホストにインストール不要
- **複数のプロジェクト間で環境を分離できる** - バージョン違いのNode.jsプロジェクトも共存可能
- **新メンバーのオンボーディングが簡単** - `git clone` → VSCodeで開くだけ

## ディレクトリ構成例

個人開発ではモノレポを活用しているため、`.devcontainer`ディレクトリ下に`frontend`ディレクトリを作成し、そこに`Dockerfile`等を置いています。

```bash
project-root/
├── .devcontainer/
│   └── frontend/               # 開発環境用設定
│       ├── devcontainer.json   # VSCode設定
│       └── Dockerfile          # 開発用Dockerfile
│
└── frontend/                   # Next.jsプロジェクト（後で作成）
    ├── src/
    ├── public/
    ├── package.json
    ├── package-lock.json
    └── next.config.js
```

## 開発環境の構築

### Dockerfile

`.devcontainer/frontend/Dockerfile`:

```dockerfile
FROM node:24-bookworm-slim

ENV DEBIAN_FRONTEND=noninteractive \
    NODE_ENV=development \
    NEXT_TELEMETRY_DISABLED=1 \
    TZ=Asia/Tokyo \
    LANG=C.UTF-8 \
    LC_ALL=C.UTF-8 \
    npm_config_update_notifier=false

RUN apt-get update && apt-get install -y --no-install-recommends \
    bash \
    git \
    curl \
    tzdata \
    ca-certificates \
    tree \
    procps \
 && rm -rf /var/lib/apt/lists/*

WORKDIR /workspace

RUN mkdir -p /workspace && chown -R node:node /workspace

USER node

EXPOSE 3000 6006 9229
```

#### Dockerfile 解説

##### ベースイメージの指定
```dockerfile
FROM node:24-bookworm-slim
```
公式のNode.jsイメージを使用。`bookworm-slim`はDebian 12の軽量版で、イメージサイズを削減しつつ必要な機能を確保しています。

##### 環境変数の設定
```dockerfile
ENV DEBIAN_FRONTEND=noninteractive \
    NODE_ENV=development \
    NEXT_TELEMETRY_DISABLED=1 \
    TZ=Asia/Tokyo \
    LANG=C.UTF-8 \
    LC_ALL=C.UTF-8 \
    npm_config_update_notifier=false
```

| 環境変数 | 説明 |
|---------|------|
| `NODE_ENV=development` | 開発モードで起動 |
| `NEXT_TELEMETRY_DISABLED=1` | Next.jsのテレメトリ（使用状況の送信）を無効化 |
| `TZ=Asia/Tokyo` | タイムゾーンを日本時間に設定 |
| `LANG=C.UTF-8` | 文字化け防止 |
| `npm_config_update_notifier=false` | npmの更新通知を無効化（ノイズ削減） |

##### 必要なパッケージのインストール
```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends \
    bash git curl tzdata ca-certificates tree procps \
 && rm -rf /var/lib/apt/lists/*
```

| パッケージ | 用途 |
|-----------|------|
| `git` | バージョン管理 |
| `curl` | HTTPリクエスト（API確認など） |
| `tree` | ディレクトリ構造の確認 |
| `procps` | `ps`コマンド等（プロセス確認） |
| `rm -rf /var/lib/apt/lists/*` | イメージサイズ削減 |

##### 非rootユーザーの設定
```dockerfile
RUN mkdir -p /workspace && chown -R node:node /workspace
USER node
```
セキュリティのため、rootではなく`node`ユーザーで実行。公式Node.jsイメージには`node`ユーザーが事前に作成されています。

##### ポートの公開
```dockerfile
EXPOSE 3000 6006 9229
```

| ポート | 用途 |
|--------|------|
| `3000` | Next.js開発サーバー |
| `6006` | Storybook |
| `9229` | Node.jsデバッガー |

### devcontainer.json

`.devcontainer/frontend/devcontainer.json`:

```json
{
  "name": "Frontend Dev Container",
  "build": {
    "dockerfile": "Dockerfile",
    "context": "../.."
  },
  "workspaceFolder": "/workspace",
  "workspaceMount": "source=${localWorkspaceFolder},target=/workspace,type=bind",
  "forwardPorts": [3000, 6006, 9229],
  "remoteUser": "node",
  "updateRemoteUserUID": true
}
```

#### devcontainer.json 解説

| 項目 | 説明 |
|------|------|
| `name` | VSCodeに表示されるコンテナ名 |
| `build.dockerfile` | 使用するDockerfileのパス |
| `build.context` | Dockerビルドコンテキスト（プロジェクトルート） |
| `workspaceFolder` | コンテナ内の作業ディレクトリ |
| `workspaceMount` | ホストのプロジェクトをコンテナにバインドマウント |
| `forwardPorts` | ホストにフォワードするポート |
| `remoteUser` | コンテナ内でのユーザー（`node`） |
| `updateRemoteUserUID` | ホストとコンテナのUID/GIDを同期（権限問題を防止） |

## 使用方法

### 1. 開発環境の起動

1. VSCodeでプロジェクトルートを開く
2. `Cmd/Ctrl + Shift + P` → `Dev Containers: Reopen in Container`
3. `Frontend Dev Container`を選択
4. 初回はビルドに数分かかる
5. コンテナ内のターミナルが開く

### 2. Next.jsプロジェクトの新規作成

コンテナ内のターミナルで以下を実行します：

```bash
# frontendディレクトリにNext.jsプロジェクトを作成
npx create-next-app@latest frontend
```

対話形式で設定を聞かれます：

```
✔ Would you like to use TypeScript? … Yes
✔ Would you like to use ESLint? … Yes
✔ Would you like to use Tailwind CSS? … Yes
✔ Would you like your code inside a `src/` directory? … Yes
✔ Would you like to use App Router? (recommended) … Yes
✔ Would you like to use Turbopack for `next dev`? … Yes
✔ Would you like to customize the import alias (@/* by default)? … No
```

> **ポイント**: プロジェクト名を`frontend`にすることで、`/workspace/frontend`ディレクトリにNext.jsプロジェクトが作成されます。

### 3. 開発サーバーの起動

```bash
# frontendディレクトリに移動
cd frontend

# 開発サーバー起動
npm run dev
```

ブラウザで `http://localhost:3000` にアクセス

## 既存プロジェクトの場合

既にNext.jsプロジェクトが存在する場合は、プロジェクト作成をスキップして以下を実行します：

```bash
# frontendディレクトリに移動
cd frontend

# パッケージインストール
npm install

# 開発サーバー起動
npm run dev
```

## カスタマイズ例

### VSCode拡張機能の自動インストール

開発に便利な拡張機能を自動インストールするには、`customizations`を追加します：

```json
{
  "name": "Frontend Dev Container",
  "build": {
    "dockerfile": "Dockerfile",
    "context": "../.."
  },
  "workspaceFolder": "/workspace",
  "workspaceMount": "source=${localWorkspaceFolder},target=/workspace,type=bind",
  "forwardPorts": [3000, 6006, 9229],
  "remoteUser": "node",
  "updateRemoteUserUID": true,
  "customizations": {
    "vscode": {
      "extensions": [
        "dbaeumer.vscode-eslint",
        "esbenp.prettier-vscode",
        "bradlc.vscode-tailwindcss",
        "styled-components.vscode-styled-components"
      ],
      "settings": {
        "editor.formatOnSave": true,
        "editor.defaultFormatter": "esbenp.prettier-vscode"
      }
    }
  }
}
```

### 起動時のコマンド実行

コンテナ作成後に`npm install`を自動実行するには、`postCreateCommand`を追加します：

```json
{
  "name": "Frontend Dev Container",
  "build": {
    "dockerfile": "Dockerfile",
    "context": "../.."
  },
  "workspaceFolder": "/workspace",
  "workspaceMount": "source=${localWorkspaceFolder},target=/workspace,type=bind",
  "forwardPorts": [3000, 6006, 9229],
  "remoteUser": "node",
  "updateRemoteUserUID": true,
  "postCreateCommand": "cd frontend && npm install"
}
```

## デバッガーの使用

VSCodeの「実行とデバッグ」からNode.jsデバッガーを使用できます。

`.vscode/launch.json`を作成：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Next.js: debug server-side",
      "type": "node-terminal",
      "request": "launch",
      "command": "npm run dev",
      "cwd": "${workspaceFolder}/frontend"
    },
    {
      "name": "Next.js: debug full stack",
      "type": "node-terminal",
      "request": "launch",
      "command": "NODE_OPTIONS='--inspect' npm run dev",
      "cwd": "${workspaceFolder}/frontend"
    }
  ]
}
```

ポート`9229`でデバッグ接続が可能です。

## Docker Composeを使わない理由

今回の構成では、Docker Composeを使用していません。その理由は：

1. **単一コンテナで完結** - フロントエンドのみの開発ではDBなどの追加サービスが不要
2. **シンプルさ** - 設定ファイルが少なく、メンテナンスが容易
3. **起動が速い** - Docker Composeのオーバーヘッドがない

バックエンドAPIやデータベースが必要な場合は、Docker Composeを使った構成を検討してください。

## おわりに

Devcontainerを使うことで、環境構築の手間を大幅に削減し、チーム開発をスムーズに進められます。

特にフロントエンド開発では、Node.jsのバージョン管理（nvmなど）やグローバルパッケージのインストールが不要になり、プロジェクトごとに完全に分離された環境で開発できます。

今回紹介したシンプルな構成をベースに、プロジェクトの要件に合わせてカスタマイズしてみてください。
